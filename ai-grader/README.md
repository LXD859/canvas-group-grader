# AI 作业初评工作台

本工具面向 Canvas 小组共享评分作业，支持手写 PDF、PNG 和 JPEG。它将题目、评分标准、选定小组的提交文件以及你的批阅要求整理为任务包，交给 Codex 或其他能查看文件页面的 Agent 初评。结果导入本机页面后，可以逐题检查原件、修改扣分、合并同事的部分表格，再导出所选范围的扣分表。支持导出任务包和直接连接视觉模型 API 两种方式，没有 Canvas 成绩写入接口。

## 启动

Windows 上安装 Python 3.11 或更高版本，双击本目录的 `start.bat`，打开 <http://127.0.0.1:8001>。首次启动会下载依赖。窗口中按 Ctrl+C 关闭服务。这个目录可以单独复制使用，不依赖旁边的上传器目录。

macOS、Linux 或手动运行时，在本目录执行：

```sh
python -m venv .venv
# macOS / Linux: source .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn grader.main:create_app --factory --host 127.0.0.1 --port 8001 --workers 1 --no-access-log
```

保持单进程、本机绑定。默认数据目录是本项目的 `data/`，也可以设置 `AI_GRADER_DATA_DIR`。数据以完整 JSON 快照原子保存，附件独立存放；停止后重启可以继续复核。Token 仅在当前服务内存中保留，闲置八小时或重启后重新连接。此版本适合一位助教在自己的电脑上使用。

## 第一次试批

1. 先点「打开匿名演示」。它生成两个虚构小组和简单的微积分 PDF。可以下载演示结果，再在「导入初评」中选择该 JSON 文件，体验复核。演示结果是固定的合成测试数据，未调用 AI。
2. 正式试用时，连接 Canvas，选择课程及第一次作业，创建批阅项目。先勾选少量小组，点击「下载选中小组及题目」。下载完成的文件会保留；失败附件可以重试。每组当前提交按附件编号去重，小组缺交或附件不完整会显示出来。
3. 检查题目附件。若题目位于课程页面、外部链接或当前不支持的文件中，手动补充 PDF／图片；参考答案也可以补充。小组提交可手动添加多份文件，确认全部正确后点击「确认材料已齐」。
4. 在第 02 步填写负责题号（如 `E1,E3`），点击「更新题目选择」，再下载「评分标准准备包」，将页面显示的本机文件夹路径交给 Agent，请它阅读 `START_HERE.md` 并生成 `rubric.json`。Agent 只为所选题目生成标准，所选分值之和可以小于作业满分。导入草案后检查分值与细则，再保存确认。也可直接逐题录入。
5. 核对已保存的题目和小组范围，填写可选的额外批阅要求，然后生成任务包。每次生成都会保留独立任务编号和版本。页面显示已解压的本机文件夹路径，可以直接交给 Agent，不必再手动解压。
6. 请 Agent 阅读任务目录里的 `START_HERE.md`，实际查看相关作业页面，根据模板生成 `results.json`。在第 04 步导入该文件；同一任务可分批导入不同的小组／题目，但同一条结果不能重复导入。需要重批时生成新任务。
7. 在第 05 步选择小组，查看右侧原始 PDF 的逐页预览，核对每题建议扣分和依据。中文说明供教师查看，英文短评供学生查看，必要时修改后逐题确认。也可点击「确认本组全部题目」或「确认全部已选小组」；未批阅、有疑点或候选冲突的结果会跳过，并提供跳转入口。全对题也要明确确认零扣分。
8. 只完成自己负责的部分时，导出「部分批阅表」。已保存范围全部确认后，即可导出 Excel／CSV，不要求确认范围外的题目或小组。分题批阅时应先合并所有负责人的扣分，再交给独立上传器计算整份成绩；上传器仍以作业满分减去表中扣分计算分数。

每次导出的文件也会写到 `data/<项目编号>/exports/<输出编号>/`，页面会显示具体路径。任务包同时保存 ZIP 和解压目录，浏览器未弹出下载时仍可从本机位置取得。文件不会自动发给外部 AI 服务；你将任务包交给 Agent 时，会包含所选作业原件。

## 多人分别批阅不同题目

各人可先选择负责题目，再生成对应评分标准。也可通过「导出标准供同事使用」共享标准；同事先填写负责题号，再导入对应标准。需要合并其他题目的结果时，先扩大本项目题目范围并补齐评分标准。各自创建的项目可以不同，只要来自同一 Canvas 课程和作业，且采用相同题号、分值、评分细则，就能合并本工具导出的部分批阅表。

合并旧的人工扣分表时，第一列填写小组名称，列标题可自定义，现有表里的 `文本` 和常用的 `Group` 均可；后续列标题使用标准里的题号。Excel 优先读取 `Assignment Grading` 工作表，CSV 支持 UTF-8、UTF-8 BOM 和 GB18030。上传前请在页面明确勾选该表已完成的题目，只有这些题目的空白单元格会被解释为零扣分。其他题目仍为未批阅。普通扣分表示例：

```csv
Group,E1,E2
Example Group 1,"-1, Incorrect evaluation.",
Example Group 2,,
```

本工具导出的部分批阅表包含状态和项目来源，未批阅及待人工判断的行会跳过，不会变成零扣分。所有导入结果均作为候选保留；相互冲突时会清除该题的当前确认标记，要求人工选择。其他题目的已确认结果保持不变。普通人工表没有课程来源标识，操作前需要自行核对小组和作业。

可上传表首列为 `Group`，其他列按题号排列，每格为 `-1.5, English reason.`；零扣分留空。输出接口只检查已保存范围内的题目和小组；缺少确认时页面提供按钮跳转到对应题目。英文短评限一句话或几个词组，最多 1000 字符、100 个词；中文解释、原件依据和疑点不会写进学生扣分表。多个同名小组会阻止导出，避免上传器按名称匹配错误。

## 任务与结果约定

任务包包含 `START_HERE.md`、`manifest.json`、`results.template.json`、题目材料和所选小组的提交文件。manifest 固定任务版本、标准版本、提交次数和选题范围；任务包没有 Token。Agent 结果使用以下结构：

```json
{
  "project_id": "保留模板原值",
  "task_id": "保留模板原值",
  "version": 1,
  "rubric_version": 1,
  "results": [
    {
      "group_id": "保留模板原值",
      "question_id": "E1",
      "status": "preliminary",
      "deduction": "1.5",
      "reason": "Missing justification for the final step.",
      "reason_zh": "最后一步缺少推导依据。",
      "evidence": "submissions/.../file.pdf，第 2 页 E1：最后一步没有说明依据。",
      "doubts": ""
    }
  ]
}
```

`preliminary` 表示已初评，要求明确扣分和页面依据；`needs_review` 表示待人工判断，要求填写疑点；`ungraded` 表示未批阅，扣分必须为 `null`。扣分采用正数表示扣除的分值，导出上传表时由程序添加负号。接口校验项目、任务、标准版本、选题范围、重复记录、扣分上限和必要依据；JSON 内的数字不会代替人工确认。

修改已确认的评分标准会创建新版本并归档旧结果；旧版本任务无法导入当前结果。再次下载时会核对选中小组的当前提交，提交有变化的组会归档旧结果并重新下载。手动补充小组文件也会归档该组旧结果。题目正文和评分标准来自创建项目时的快照；教师更改作业题目或总分时应新建项目。

## 项目范围与管理

小组按编号自然排序，4 排在 10 前。点击「调整小组范围」可以展开其他小组；取消勾选后点击「更新小组选择」，会移出取消小组的原件及已有导出副本，使新的项目包保持最新范围。旧任务若包含已取消的小组或题目，将无法继续导出或导入。移出的文件保存在 `data/.scope-trash/`，当前项目不再使用；重新加入小组后需要重新下载。用户另行复制到其他位置的包不会被程序修改。

项目选择区提供删除按钮，将整个项目移入 `data/.trash/`；展开「项目回收站」即可恢复。当前项目还可重命名。旧项目首次打开时，从最近一次任务恢复所选小组和题目；没有任务的项目采用已有下载和标准，可以在页面更新范围。

新任务要求扣分结果同时给出英文 `reason` 和中文 `reason_zh`，依据和疑点也要求用中文。旧任务结果可以继续导入；缺少中文说明时页面提示补填，不会自动翻译旧评语。

## 限制与恢复

第一版仅支持已发布、按分数／百分比评分的小组共享成绩作业。个人提交、匿名评分、审核评分、外部工具提交和无附件提交需要后续扩展或手动补充。每个附件上限 200 MB，单次任务原文件总量上限 1 GB；材料较多时拆成几批小组。表格上限 10 MB、10000 行、200 列，公式不执行并拒绝导入。PDF 预览在本机逐页渲染，损坏或加密文件可下载原件后处理。

下载中断时已完成文件保留，重新连接后选择原小组继续下载。已确认结果需要点击保存才能跨重启保留，正在输入的未保存草稿只在当前页面内保留。全部批阅记录可导出为 JSON，包含历次评分标准、任务和归档结果；完整迁移本机项目时复制整个 `data/`，并保持单个服务使用该目录。

若出现 Windows 10013，表示当前服务进程的网络访问被系统限制。在原有 conda 终端启动前，应先停止占用 8001 端口的旧测试服务；仅刷新网页或重新激活终端环境不会改变已经运行的服务。证书错误、代理错误、超时及账号权限不足会分别显示对应提示。重启服务后需要重新填写 Canvas Token。

真实学校账号的读取权限、具体作业附件和 AI 识别质量尚需在实际课程试验。建议先用少量已人工批阅的作业对照，检查手写识别、替代解法和扣分尺度，再扩大批次。

## 开发、测试与打包

```sh
python -m pip install -r requirements-dev.txt
python -m pytest
python scripts/package_release.py
```

测试仅使用合成材料和模拟 Canvas，不连接真实课程。覆盖任务范围、标准版本、未知题目、重复结果、扣分范围、未批状态、合并冲突、同组去重、多附件下载中断、重启恢复、PDF 预览及本机访问限制。在两个项目同处仓库时，还会将导出文件送入原上传器解析，核对总分和格式。

打包脚本仅收集源码、说明、依赖及测试，不打包 `data/`、Token、用户材料或导出内容。API 路由要求 `X-Grader-Local: 1`，拒绝跨站请求；只有 Canvas 读取需要内存会话，本机已有项目可离线复核。主要接口包括项目创建与读取、后台附件下载、评分标准确认、任务包生成、JSON 结果导入、表格合并、逐题确认和导出。PDF/图片文件通过项目内文件编号访问，任意本地路径不会作为接口输入。


## 复核导航和扣分评语

逐题复核区的「下一组」按已选小组的编号顺序切换，到最后一组时禁用；未保存的输入保留在当前页面草稿中，点击确认后才写入项目。导出被未确认项阻止时，固定在页面上方的提示条内会出现「前往 小组 · 题号」按钮，点击后切换小组并高亮对应题目。

学生评语输入框直接使用上传表的单元格格式，例如 `-1.5, E2(b): Missing justification for the final step.`。修改前面的扣分数值时，会同步确认扣分框；修改确认扣分框时，会同步评语前缀，保存时还会检查两者一致。零扣分留空。系统内部继续分别保存分值与原因，因此导出不会重复添加负号和分值。

原因应当描述具体缺失步骤或错误，并标明题号、小问。多处扣分可用分号列出各小问、各自扣分和原因。AI 新任务包含这一要求，并避免建议式表达，例如 Please、Consider、You should。旧结果导出时自动补上题号；原结果未记载的小问需要人工补充，程序不推测。中文说明仍只用于内部复核。

复核区提供「零扣分小组一键通过」：检查已保存范围内的全部小组，只为所有所选题目均已初评为零扣分、无疑点且没有未解决冲突的小组确认。已有人工确认结果保留；有扣分、未批阅或本页未保存修改的小组整组跳过，页面显示通过数量和跳转入口。此操作只保存本机确认状态，不上传 Canvas。

新生成的批阅任务包要求评语在 100 个英文词、1000 个字符内写清具体对象、错误或遗漏的证明条件，仅使用常见数学术语和题目已出现的术语，避免 finite-tail 等未定义标签及空泛评价。此要求同时用于评分标准草案；已交给 Agent 的旧文件夹不会自动更新，请重新下载任务包并让 Agent 重新阅读 START_HERE.md。


## API 自动批阅

打开项目后切换到「API 自动批阅」，填写 HTTPS 服务地址（包括服务要求的 /v1 等前缀）、API Key 和视觉模型名称。第一版使用兼容 OpenAI 的 Chat Completions 接口；可填写完整 /chat/completions 地址。点击「连接并测试视觉输入」只发送合成图片，检查颜色识别和 JSON 返回，可能产生少量费用。程序不会自动更换服务地址或模型。连接测试通过不代表该模型能容纳任意长度的作业。

服务地址和模型名保存在项目中；密钥仅保留在当前服务会话内存，闲置八小时或重启后重新填写。密钥不会写入项目、任务包、日志或浏览器持久存储，也不会把 Canvas Token 发给模型。

选择题目后点击「生成评分标准草案」，核对服务、题目和材料，确认发送。完成后草案填入编辑器；编辑器已有新修改时保留修改，可手动载入草案。草案需由用户保存确认，再点击「开始批阅」。批阅前同样展示目标服务与发送范围。任务包含题目文字、题目及参考答案页面、当前标准、额外要求和该小组全部附件页面。多个小组逐个调用，结果自动进入复核，不会自动确认或上传成绩。

PDF 在本机逐页渲染，图片转换为视觉输入，附带文件编号、用途和页码。每组最多 100 页／张，完整请求最多 40 MB（包括图片编码和提示内容）；这些是 API 请求限制，与本地单附件 200 MB 限制不同。超过容量会明确失败，不截断页面。服务自身的上下文或图片上限可能更低；此时检查所用模型容量、拆分材料或减少题目后创建新任务。

默认跳过人工确认题目；勾选重批后新增候选并保留历史。网络错误、429 和暂时性服务器错误最多重试两次，鉴权、容量或 JSON 校验错误不会自动重试。超时后的重试可能重复计费。每组必须返回完整且合法的题目集合才能导入，缺题、重复、超分或格式错误会整组保留为失败状态。

点击停止后不再请求下一组，当前已发送请求仍可能完成并保存。重启不会自动恢复付费调用；重新连接原地址和模型后手动重试未完成项。期间改变范围、标准或材料后需创建新任务。API 任务运行时锁定该项目的修改和删除操作，其他项目可继续使用。密钥断开不代替停止按钮，已启动任务需另行停止。

## 回收站与永久删除

「删除所选项目」移动到批阅器自己的 `data/.trash`，它与 Windows 回收站相互独立。项目与回收站列表读取实际磁盘内容，返回窗口时自动刷新，也可点击「刷新项目与回收站」。外部删除的目录不会继续出现在刷新后的列表里。

选择回收站中的项目，再点击「永久删除所选项目」并确认，会删除该项目的原件、记录、导出文件以及 `data/.scope-trash` 中对应的历史移出材料。此操作无法恢复，且只作用于所选回收站项目。放在其他目录、已经交给其他人的文件副本不受影响。

API 请求结构参考官方 Chat Completions 文档：https://developers.openai.com/api/reference/resources/chat 。测试使用模拟服务和合成作业；真实账号连通性与实际模型识别质量需在用户配置后试批。
